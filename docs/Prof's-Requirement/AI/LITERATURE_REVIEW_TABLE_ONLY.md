# Literature Review Table (Related Work)

| Work | Focus / Problem | Method / System | Key Takeaway (high level) | Relation to this project (RCA Agent) | Contributions |
|---|---|---|---|---|---|
| **Yao et al. (2022)** — *ReAct: Synergizing Reasoning and Acting in Language Models* | Improve multi-step task solving by interleaving reasoning and tool use. | ReAct loop: Thought → Action → Observation (iterative). | Reasoning traces + actions can improve reliability vs. pure prompting for interactive tasks. | Direct inspiration for the agent loop (`MinimalReactAgent`) and tool-driven debugging workflow. |
| **Lewis et al. (2020)** — *Retrieval-Augmented Generation (RAG)* | Reduce hallucination / improve factual answers by retrieving external context. | Retrieve top-k documents → condition generation on retrieved passages. | External retrieval helps compensate for model memory limits and outdated knowledge. | Motivates the local retrieval layer (ChromaDB) + caching to reuse prior successful analyses. |
| **Brown et al. (2020)** — *Language Models are Few-Shot Learners (GPT‑3)* | Show in-context learning from examples without fine-tuning. | Few-shot prompting (10–100 examples) inside the context window. | More examples can improve performance, but context budget becomes a bottleneck. | Provides the baseline idea that was tested; this project’s notes report **templates/structure** can beat “more examples” for a 7B local model. |
| **Chen et al. (2023)** — *Teaching Large Language Models to Self‑Debug* | Improve correctness via iterative debugging using feedback. | Generate → explain → run/observe errors → revise. | Execution/observation feedback supports iterative improvement. | Supports “tool feedback → refine” design used in RCA analysis (parsers, file reads, LSP lookups). |
| **Jimenez et al. (2024)** — *SWE‑agent* | Automate real software engineering tasks via an agent interface. | ReAct-style agent + specialized agent-computer interface (editing/search/navigation). | Tool/interface design materially affects agent success on real issues. | Justifies investing in a rich tool surface (19 tools) and IDE integration (VS Code extension). |
| **Cloud code assistants** (e.g., Copilot/ChatGPT-class systems) | General-purpose coding + debugging support. | Large proprietary models served via cloud APIs. | High capability but constrained by privacy, cost, rate limits, and context handling. | Serves as contrast: this project prioritizes **local-first privacy** and unlimited iteration; later adds optional cloud models as a hybrid mode. |
| **Local agent frameworks** (e.g., LocalAI / Cline-style local tooling) | Run models locally with generic developer tools. | Local inference + generic file/search/edit tools. | Demonstrates feasibility of local-first workflows, but often generic (not domain-specific). | This project adds **Android/Kotlin specialization** (26+ error parsers + structured prompts) plus strong testing discipline. |
| **RCA Agent (This Work, 2025–2026)** | Local-first root-cause analysis for Kotlin/Android errors inside VS Code. | ReAct-style agent + 26+ parsers + tool execution + local retrieval (ChromaDB) + caching; local Ollama model (DeepSeek‑R1‑Distill‑Qwen‑7B). | Project evidence emphasizes: (1) domain specialization improves signal-to-noise, (2) structured prompt templates help small models, (3) local-first enables privacy + repeated iteration. | **Latest status (Mar 2026):** Cloud LLM configuration (Gemini/Claude/OpenAI) with provider auto-detection + secret storage is implemented; runtime analysis integration is still in progress. Error Queue bug RCA identified ID-collision root cause; ongoing dashboard/UX improvements. Reported metrics in repo docs include ~3.91s average latency (benchmark), ~99% test pass rate (878+ unit tests), and 26+ supported error types. |
